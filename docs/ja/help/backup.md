# メモ・コメント・復元データを保護する

## できること

索引から再生成できない原本とユーザー記録を保護します。

## 始める前に

本文と AI 下書きを保存し、外部編集・同期を止め、正常に終了します。

## 操作手順

1. 非表示の `.vault-rag/`、添付、HTML、デザインを含む保管庫全体をバックアップします。
2. `annotations.sqlite` はコメントとハイライトです。履歴・ごみ箱・添付整理の原本も復元用データで、キャッシュではありません。
3. 設定・モデル・認証情報・AI 履歴は通常 Windows の `%LOCALAPPDATA%\VaultRag`、Mac の `~/Library/Application Support/VaultRag` にあります。
4. 唯一の未保存下書きは別途書き出し、バックアップを読めるか確認します。
5. 新しいフォルダーに復元して確認してから既存資料を置き換えます。

添付サーバーを使う場合は、保管庫が利用してきたすべてのサーバールートにある原本（現在のアップロード先以外も含む）と、設定済みの各メタデータディレクトリもバックアップします。既存のメモのリンクが使えるよう、ストレージ ID、相対パス、メタデータディレクトリの対応関係を維持します。移行後の原本はサーバーにしかない場合があります。サムネイル、ローカルキャッシュ、カタログは原本の代わりにはなりません。

復元は別の保管庫で確認します。サーバー添付がある場合は、クライアントのキャッシュが空の状態で、別途復元した検証用のサーバーコピーに接続します。既存のメモのリンクからローカルの原本とサーバーにしかない原本を一つずつ開き、元ファイルの SHA-256 チェックサムと照合します。添付グループやカバーを使っている場合は、それらの復元も確認します。サムネイルが見えても、原本を取り出せるとは限りません。

## 完了後の状態

完全なバックアップには、原本とユーザー記録が含まれます。ローカルの索引やごみ箱だけでは別端末のバックアップになりません。

## うまくいかないとき

別のコンピューターでは OS 暗号化された認証情報の再認可が必要な場合があります。バックアップを公開しないでください。
