# 添付を閲覧・プレビュー・アップロードする

## できること

ローカルとサーバーのファイルを同じ画面で探し、グループで整理し、原本を必要時に取得します。

## 始める前に

簡潔なサーバー設定、自動走査の再開、独立ダウンロードページは [LeafLoom 0.1.5](../RELEASE_NOTES_0.1.5.md) から利用できます。更新前に保管庫をバックアップし、アプリのデータを保持してください。添付サーバーは任意で、未設定時はローカルの `_attachments` に保存します。**添付ファイル** で端末の目録を準備すれば閲覧・プレビュー・アップロードができます。

**設定 → 添付サーバー** でアドレス、アカウント、パスワードを登録し、**保存して接続** を選びます。HTTP(S) は WebDAV、`smb://host/share/subfolder` と Windows 共有パスは SMB2/3 です。ブランドの選択やシステムのマウントは不要。公開 WebDAV は HTTPS、既存の数値プライベート／VPN HTTP は引き続き利用できます。公式クライアント経由ではクライアントと指定ポートを使用可能に保ちます。Tailscale は **direct**（DERP 中継以外）を優先し、同一 LAN では NAS の LAN IP とポートに切り替えます。接続テストで往復遅延を表示します。**添付ファイル** で **ローカル** を選ぶと端末のみの高速一覧になり、リモート項目の **ローカルにキャッシュ** は保管庫キャッシュへ実体化します（新しいディレクトリ庫メンバーは作りません）。

メンバーはサーバー資料ディレクトリ下の **アプリ書き込みディレクトリ庫**（`…/attachments/v1/members/`）に切り替えられます。**同期状況** で現行 NAS ツリーに対し一度 **既存ファイルをディレクトリ庫へ取り込み** すると、以降は全ツリー自動発見を止め、アプリのアップロード／移行とディレクトリ庫の pull のみをメンバーとします。取り込みはメンバー登録のみで、**原本はダウンロードしません**。既定のリモートサーバーがあるとき、中央の貼り付け／アップロードは一時的に `_attachments` へ置きサーバーへ上げます。**ノート向けサイズの画像は端末キャッシュとして残し**埋め込みをすぐ開けるようにし、大きい／非画像の仮置きは削除して一覧は軽量サムネ／プレビューのみにします。他の原本は **ローカルにキャッシュ** または開くまでサーバーに残ります。低速回線や切断時も完了まで再試行し、認証失敗のときだけ自動再試行を止めます。

同じページの **サーバーへのアップロードと移行タスク** でローカル `_attachments` を選択サーバーへ移せます。保管庫相対パスを1行ずつ指定でき、空欄なら添付フォルダー全体をプレビューします。登録済み HTML プロジェクトの木とデザイン／プロジェクト資源はサーバー移行の対象外です。確認後に実行し、失敗や切断時は同じジョブの **この移行を続行** だけを使います。検証後の原本はサーバー、ローカル同パスは版一致キャッシュで、キャッシュ削除は端末側のみです。プレビューが 0 件で除外のみなら除外を開き端末側ルールを確認してください（サーバー既存で見つからないわけではありません）。外出時は Tailscale `100.x` と小バッチ（約 50～200 パス）、スリープ防止；自宅では LAN を優先。[全体ガイド](../GUIDE.md#添付サーバーと自動同期)を参照してください。

`_attachments` 下に残る登録済み HTML プロジェクトは、一度きりのスクリプト `scripts/localize_html_attachments.py` で移せます（既定はプレビュー、LeafLoom 終了後に `--apply` で書き込み）。プロジェクトを `Web/<名前>/` へ、外部の中央依存を各プロジェクトの `assets/` へ移し、静的な HTML/CSS 参照を書き換えます。スクリプト由来の参照はブロッカーとして報告されます。

共有 DUFS サーバーでは、自分のアカウント用アドレスと認証情報を使用します。[一つのコンテナーでアカウントを分離する手順](../DUFS_MULTIUSER.md)に管理者設定と DJ の移行方法を記載しています。

## 操作手順

1. **ローカル**は端末のファイル名索引と原本を使用し、サーバー目録は読みません。**すべて**はローカル添付を先に表示し、保存済みのサーバー目録を選択中の並び順で統合します。**サーバー**と個別サーバーは保存済み目録のみを読み、一覧を開いても索引の初期化やサーバー走査は行いません。サーバー目録が利用できない場合も、ローカル結果は絞り込みと独立したページ送りを維持し、再試行すると最新の先頭ページに戻ります。外部でのファイル変更は端末索引の更新後に反映されます。
2. 名前／パス、種類、並び順、グリッド／一覧を使います。グループは手動または保存元・ディレクトリ・形式・分類・タグで作れます。切り替え時は見出しを変え、前の一覧を消して読み込み状態を示します。失敗後の再試行も同じグループを読みます。
3. **添付ファイル情報** を開いて選択したファイルを確認します。情報欄は初期状態で閉じ、設定を保持。画像・PDF・音声・動画は従来のビューアーを使い、他の形式は原本を取得せず既存表紙を表示します。表紙がなければアイコンと取得操作を表示します。 プレビューとサムネイルは有効な端末ファイルまたは範囲キャッシュをすぐに使用し、サーバーの版をバックグラウンドで確認します。未取得の内容は必要時に取得します。版の変更は後続の読み取りに適用し、応答中の内容に異なる版を混在させません。ダウンロードは従来の同期検証を維持します。
4. アップロードまたはドラッグでファイルを追加し、同名の原本も保持します。ノート・フォルダー作成や取り込みはディレクトリ操作で行います。サーバーの編集・無効化・新規保存先への指定でも既存の添付は移動しません。
5. **同期状況** に添付数、走査済み／待機中、再利用数と再試行を表示します。端末の再開位置で切断・再起動後に続行します。自動処理はサーバーごとに順番に行い、一台で同時に読むのは二つまで。変更のないアーカイブは最長1週間まで確認間隔を延ばし、アップロード先は約2時間を維持します。期限が来た子は個別に照合します。**全ディレクトリを確認** はキャッシュを使わず、原本を取得しません。
6. **ダウンロード** で原本の準備と ZIP を確認します。検証後に端末へ保存し、容量はダウンロード設定で変更します。一時保存の解放でサーバー原本は消えません。名前変更・移動・回収は参照と版を検証し、サーバーにより使用できる操作が異なります。

### 資料、AI の範囲とサーバールール

分類、タグ、個人ノート、出典情報と実際の表紙は同じファイル一覧へ反映します。固定の製品画面はグループに置き換えましたが、互換ツールと任意の Unity 情報取得は保持します。グループと資料は検証した記録で同期し、競合を明示。稼働中の SQLite、送信待ちとキャッシュを端末のアプリデータに保管し、単なるキャッシュとして同期・削除しないでください。

必要なグループだけで **AI 素材検索の対象にする** を有効にします。未選択では全体を検索しません。AI は資料／プレビューを確認し、原本を検証して指定ローカル保存先へ渡します。Unity への自動取り込みや購入確認は行いません。[全体ガイド](../GUIDE.md#添付ファイルの管理)も参照してください。

サーバールートや子に可視の `leafloom.ignore` を置き、Gitignore 形式で除外できます。先頭行は厳密に `# leafloom-ignore v1` とし、子ルールや `!` で再包含します。読み取りに NAS の書き込み権限は不要。全走査成功時に反映し、原本・ID・参照を保持します。

### MCP で通常の添付をアップロード

Base64 一括送信には、この変更を含むビルドが必要です。

ナレッジベースの添付は `vault_files_update` の `request.action="upload"` を使います。ChatGPT では `source="files"` とホストが提供するトップレベルの `files` 配列を優先します。ローカルクライアントは `source="base64"`、`name`、`data_base64`、元バイト列の `sha256` により 2 MiB 以下を一括送信できます。それ以上は begin/chunk/commit を使います。`folder` を省略すると設定済み添付フォルダーを使い、`Comics/Project/assets` などの保管庫内相対パスも指定できます。

`vault_index_status` の `workspace_revision` と一意の `operation_id` が必要です。同一引数の再試行では同じ ID を使います。結果は保存先、サイズ、SHA-256、リビジョン、`markdown_link` を返し、画像には `markdown_embed` も返します。`vault_files` の stat に `source_note` を指定するとノート相対リンクを取得できます。ノートの現在のリビジョンを使って Markdown を更新してください。同名の元ファイルは保持されます。

Design Studio のインポートや Feishu の一時転送しか表示されない場合、サーバーの `tools/list` に `vault_files` と `vault_files_update` があるか確認します。更新済みバックエンドの再起動に加え、クライアントのプラグインツール一覧を更新／再スキャンしてください。LeafLoom の再起動だけではクライアントのキャッシュは更新されません。保管庫の書き込み権限も確認してください。通常の添付に Feishu 権限は不要です。[MCP ファイルツール](mcp.md)を参照してください。


### 添付ファイルの種類

**設定 → 添付サーバー → 添付ファイルの種類** で許可する拡張子を編集し、**保存** します。ローカルファイル、設定済みの全サーバー、添付管理からのアップロード、エディターへの添付挿入、MCP 添付アップロードで共通です。既定では一般的な画像（SVG を含む）、PDF／Office、音声・動画、圧縮ファイル、フォント、電子書籍、`.unitypackage` を含みます。Web ページやスクリプトなどのソースは既定で対象外ですが、通常のファイルインポートは利用できます。

カンマ、空白、改行で区切ります。`PNG` は `.png` に統一し、重複を除去します。大文字と小文字を区別せず、`.tar.gz` などの複合拡張子にも対応します。パスとワイルドカードは使用できません。空欄の場合は添付を認識しません。**既定の種類に戻す** で既定一覧を入力し、確認後に保存できます。この端末にワークスペースごとに保存し、端末間では自動同期しません。

拡張子を削除すると、既存索引を含む添付一覧、グループ、AI 素材検索、件数・容量にすぐ反映します。追加時は索引済みローカルファイルに即時反映し、サーバーでは次回のスキャン後に表示します。ディレクトリキャッシュは再利用できます。サーバーの `leafloom.ignore` は引き続き有効で、`!` でも許可一覧外の種類は含められません。元ファイル、メタデータ、ID、既存リンクは保持します。未完了の添付アップロードは公開前に種類を再確認し、無効化された場合は復旧用データを保持します。移行の依存関係保護と対応形式の制限も維持します。


### バックグラウンド確認、ディレクトリ庫と走査範囲

起動時は保存済みの添付一覧をすぐ表示します。**アプリ書き込みのみ**（ディレクトリ庫権威）のときは、バックグラウンドは主にメンバーディレクトリ庫を pull し、全ツリー発見は行いません。一覧はその完了を待ちません。まだ **ディレクトリ確認** モードのときは、アップロード先は約2時間、安定アーカイブは最長1週間まで間隔を延ばします。LeafLoom のアップロードは端末投影をすぐ更新します。商品資料とグループの取得はアイドル時に2時間から最長6時間へ延ばします。転送失敗は退避再試行し、切断・再起動後も成功またはキャンセルまで残ります。認証失敗のときだけ自動再試行を止めます。

ディレクトリ庫取り込み後、LeafLoom 以外で NAS に置いたファイルは、再取り込みかディレクトリ確認モードに戻すまで一覧に出ません。**今すぐ同期** でディレクトリ庫を pull し、**全ディレクトリを確認** はディレクトリ確認モードのときだけ使えます。

他のツールによる変更は次回確認まで反映されません。安定したアーカイブでは最長1週間、資料やグループでは最長6時間かかる場合があります。すぐに確認するには **全ディレクトリを確認**、資料には手動同期を使用してください。NASへの追加サービスは不要です。サーバーの変更通知ではなく定期確認を利用します。

**設定 → 添付サーバー** でサーバーを編集し、**サーバーの走査対象ディレクトリ** に設定済みサーバールートからの相対パスを1行ずつ指定します。空欄は全体です。一覧に表示したいアップロード先も含めてください。この範囲は検出と一覧のみを制限し、既存の参照は無効にしません。範囲を狭めても元ファイル、別名、個人資料は削除しません。上位ディレクトリの `leafloom.ignore` も適用します。

同期状態はキャッシュ読込、実際のサーバー取得、欠落確認、参照と資料の同期を区別し、現在のディレクトリと資料の処理件数を表示します。**ディレクトリ確認を一時停止** は再起動後も有効で、完了したディレクトリの記録を保持します。**ディレクトリ確認を再開** で検出を続行します。既存の添付、ダウンロード、未送信資料には影響しません。**全ディレクトリを確認** は選択範囲のみでキャッシュを使わずに確認します。他のツールでサーバーを変更した場合、一覧への反映は次回の確認まで待つことがあります。

## 完了後の状態

背景更新では絞り込み・選択・スクロールと下書きを保持します。ページの版が古ければ **一覧が更新されました。最新を表示** を案内し、勝手に先頭へ戻りません。原本は既存の場所に残し、概要は原本とキャッシュを区別します。未準備のローカル容量はゼロではなく不明です。

## うまくいかないとき

一時的な通信問題は自動再試行し、理由は折りたたみます。再接続や同期の現在状態で過去のエラーを置き換えます。認証拒否では情報を更新してください。失敗した走査で記録を消さず、更新直後は最初の再開位置を作成します。変更履歴のないサーバーでは定期照合が必要。オフラインでは完全なキャッシュだけを使えます。

他の端末で参照を復元する際は既存の ID、論理ルート、資料の紐付けを保ってください。新規保存先の変更で原本や資料は移動しません。サーバー移行は **設定 → 添付サーバー**。ローカル整理の入口は非表示のまま、過去のタスク記録は復旧用に残ります。
