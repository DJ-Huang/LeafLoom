# 添付を閲覧・プレビュー・アップロードする

## できること

専用ワークスペースで添付を探し、メディアをプレビューし、原本をダウンロードします。

## 始める前に

> **対応バージョン：** この添付ワークスペースと整理機能は [v0.1.4 インストーラー](https://github.com/DJ-Huang/LeafLoom/releases/tag/v0.1.4)に含まれています。v0.1.3 には含まれていません。旧版を使用している場合は、保管庫をバックアップして更新してから、以下の手順を進めてください。

ローカルフォルダーを接続します。まずはデモ保管庫で試せます。

### ローカル添付、サーバーと複数端末

サーバーは任意です。**設定 → ファイルとインポート → 添付ストレージ → 新しい添付の保存先** は今後のアップロード先だけを変更します。既存のローカル・サーバー添付は同じ画面で出所別に閲覧でき、切り替えても原本の移動・削除・再送信・自動取得や旧参照の更新はしません。送信待ちの添付は登録時の保存先を保持します。

| 状況 | 動作 |
| --- | --- |
| ローカル専用 | ノートと原本はワークスペースに保存します。**ローカル目録を準備** で閲覧・プレビューでき、サーバーも自動整理も不要です。 |
| サーバーを選択 | 新規アップロードをそのサーバーへ保存。登録済みのサーバー添付と準備済みのローカル目録を閲覧できます。 |
| ローカル目録が未準備 | 目録が不完全と表示し、ローカル容量はゼロでなく不明とします。サーバー添付は閲覧でき、ローカル準備はサーバーを走査しません。 |
| ローカルへ戻す | 新規添付のみローカルに保存。旧サーバー添付と参照はサーバーに残り、オフライン複製や逆移行は行いません。 |
| 複数端末でフォルダー同期 | ノートと原本の相対構造を保持して同期し、各端末で目録を準備します。アプリのデータや使用中の SQLite は同期しません。 |

商品カタログ・ダウンロード設定は添付ストレージと個別に保存し、その保存ボタンは添付原本のアップロード先を変更しません。

存在するローカルの完全パスを優先し、解放済みの旧パスは検証済みのサーバー対応で解決します。他端末の削除通知がまだ届かない場合、走査でローカルコピーを削除せず、サーバー側は別の論理パスで表示します。削除到着後は旧パスと移行前 ID がサーバーへ解決します。異なるローカル・サーバー添付と同名の場合は選択せず、完全な相対パスかサーバー付きの論理パスを使用してください。新しい保存先への切替でこの優先順位は変わりません。

サーバー走査は目録と参照メタデータのみ読み取り、本体は取得しません。新規送信と移行はメタデータ領域 `attachments/v1/` に相対参照を保存し、読み戻し検証後に完了・原本解放を行います。旧版で移行した場合は旧対応を保持する端末で一度 **旧添付参照を同期** を実行します。他端末はこの機能を含む版で同じサーバールートとメタデータ領域を設定し、端末で認証して走査してください。ローカルフォルダーと設定 ID は異なっても構いません。競合は明示します。サーバーのメタデータと未送信キューを保持してください。

添付 SQLite、サーバー設定、キャッシュ、キュー、グループ、商品投影はアプリ専用の `attachment-workspaces/<workspace-key>/` に保存します。未同期のユーザーメタデータを含むため、すべてをキャッシュとして削除しないでください。ローカル専用のタグ・グループ・未完了作業は端末ごとに独立し、原本同期はすべてのアプリ情報の同期を意味しません。初回更新は旧 `.vault-rag` から整合性のあるスナップショットを取り、旧ファイルを保持します。旧アプリと同期を停止して更新してください。OS・絶対パス変更時は公開サーバー設定のみ再利用し、他端末の未完了操作は引き継ぎません。整理の復元資料は `.vault-rag/attachment-migrations/`、一時解放ファイルは同一ファイルシステムで復元できるワークスペース側に残します。

サーバーがオフラインなら保存済みの内容のみ開けます。未保存のファイルは接続エラーとなり、同名のローカルファイルで代用しません。キャッシュ削除はサーバー原本を削除しません。HTML・ソースプロジェクトと依存物は元の場所に残します。旧参照の解決は LeafLoom 内で行い、他エディターには URL と認証への対応が必要です。フォルダー同期は端末間トランザクションではありません。整理・名前変更・移動・移行は一台だけで行い、同期と他の編集を停止し、完了と同期後に別端末で作業してください。外部の同時編集では同期競合が発生し得ます。

### サーバー上の添付、ローカルキャッシュと移行

この機能にはサーバー添付に対応した新しいビルドが必要です。従来の v0.1.4 インストーラーには含まれません。

**設定 → ファイルとインポート → 添付ストレージ** で汎用 WebDAV サーバーを追加できます。接続ごとに名称、URL、サーバールート、アップロード先サブディレクトリ、専用ユーザー名を指定します。URL にパスワードは含めません。**添付設定を保存** してから **接続をテスト** し、**サーバーの添付をスキャン** してください。設定を開くだけでは NAS をスキャンしません。バックグラウンドでディレクトリのメタデータを分割保存し、添付の内容は読み込みません。中断や失敗時も検出済みの記録を保持します。新しい添付の保存先は今後のアップロードに適用され、ローカルの保存先も選べます。書き込み可能な場所はサーバーの権限で決まり、読み取り専用の素材は名前変更・移動・回収できません。

NAS 上で原本を削除・移動・追加したら、添付画面の **サーバーのディレクトリを更新** を選びます。個別サーバーの表示ではそのサーバーのみを更新します。すべて／サーバー表示で複数の接続がある場合は一つを選び、有効なサーバーが一つだけなら直接更新できます。全サーバーの自動スキャンは行いません。添付内容を読まずにディレクトリ情報を同期し、進捗と結果を表示します。全体のスキャンが成功した場合のみ、欠落したファイルを一覧と容量の集計から除外します。アセット ID・タグ・旧参照の記録は保持し、旧参照を開くと原本の欠落を知らせます。中断・失敗時は既存の記録を保持します。**登録済みの一覧を更新** はローカル索引の再読み込みだけで、NAS 上の削除は検出しません。

サーバーのルートと各サブディレクトリに、非表示ではない `leafloom.ignore` を置けます。Gitignore 形式のパス・glob・`#` コメント・`!` による再包含に対応し、子ディレクトリのルールは祖先のルールを上書きできます。除外された親ディレクトリで探索を止める Git の動作とは異なり、常に子ディレクトリを訪れてルールを読むため、子のルールで親が除外したファイルを再包含できます。既定では `.md`・`.markdown`・`.base`・`.html`・`.htm` とスクリプト／ソースコードを除外し、これらも `!` で再包含できます。`.txt`・`.json`・バイナリ・デザイン素材は保持します。ルールは NAS のファイル管理機能で編集し、LeafLoom は読み取りのみで取得するため Dufs の書き込み権限は不要です。変更後はサーバーのディレクトリを再更新してください。全体の確認成功後のみ、除外項目を添付一覧・メタデータ検索・容量の集計から非表示にします。除外は NAS 原本の削除や欠落扱いではなく、既存のアセット ID・タグ・旧参照・キャッシュを保持し、旧 ID／参照から原本を読み取れます。ルールの読み取り・解析に失敗しても、新しいルールで既存記録を部分的に非表示にはしません。修正後に再更新してください。

UTF-8 で保存してください（BOM と CRLF も使用できます）。先頭行は正確に `# leafloom-ignore v1` とし、その前に空行を置かないでください。ヘッダーの欠落・不一致時は更新を中止し、認証／エラーページをルールとして扱いません。各ファイルは 64 KiB・2,048 行まで、各行は 2,048 文字までです。次のテンプレートをルートまたはサブディレクトリへコピーし、ルールを編集できます。

```text
# leafloom-ignore v1
# このディレクトリ内の一時ファイルを除外
*.tmp
# この Markdown ファイルを添付として再包含
!reference.md
```

デスクトップ版はシステム暗号化でパスワードを保存し、起動時にバックエンドのメモリへ復元します。ワークスペース設定にパスワードは含まれません。対応するシステム暗号化 API は非同期で呼び出し、キーストアの復元を待たずにワークスペースを開きます。キーストアが一時的にロックされている場合やローカルサービスに届かない場合は、1・3・10・30 秒の間隔で回数を制限して再試行します。ロック解除、スリープからの復帰、または **設定 → ファイルとインポート → 添付ストレージ → 添付の認証情報の復元 → 認証情報の復元を再試行** で新しい再試行サイクルを開始します。キーストア・認証ファイル・ローカル同期の状態を確認でき、「ローカルサービスに反映済み」はバックエンドのメモリへの復元を意味します。サーバーの接続状態は別に確認してください。破損した認証ファイルは保持し、空の認証情報で置き換えません。ブラウザー版は現在のバックエンドプロセスのメモリにのみ保持し、再起動後は再入力が必要です。

NAS の接続障害や 502／503／504 応答では、約 2・4・8・16・32・60 秒と間隔を延ばして再試行し、最大 60 秒とします。ディレクトリ記録とアップロード待ちのファイルは保持します。正常時は約 60 秒ごとに設定済み URL のみを確認し、NAS 全体の再帰スキャンや添付内容の読み込みは行いません。401／403 応答では、明示的な **接続をテスト**、タスクの再開、または認証情報の更新まで、同じ認証バージョンでの自動試行を停止します。パスワードの変更だけでは既存タスクを再認可しません。所有者や認証情報のバージョンが変わった場合は、タスクを明示的に再開して owner／revision を再確認します。

公式クライアント経由の場合、確認済みのローカル転送 URL を指定し、公式クライアントと添付ウィンドウを開いたままにします。ウィンドウを閉じたりクライアントを再起動した場合は、手動で添付ウィンドウを開き直してください。公式セッションの再構築や新しいポートの自動検出には対応しません。同じ URL が復旧すれば自動的に検出できますが、ポートが変わった場合は URL を手動で更新します。追加認証は公式クライアントで完了し、タスクの状態に従って再開してください。

同じ LAN 内で安定して利用するには、NAS の添付サービスのアドレス（サービスのポートを含む）を指定し、**WebDAV に直接接続** を選びます。公式クライアントのウィンドウへの依存がなくなります。ルーターで NAS の IP を固定予約するか、安定した HTTPS ホスト名を使用してください。LAN アドレスはそのネットワーク内、または適切に設定した VPN 経由でのみ利用できます。接続経路だけを変更する場合は既存のサーバー設定、ルート、認証情報を保持し、保存後に接続テストと添付ファイルの表示を確認してから一覧を更新してください。

外出先から利用する場合は、NAS と LeafLoom を実行するコンピューターを同じプライベート VPN に参加させます。`100.64.0.0/10` の数値形式の共有ネットワーク IPv4 アドレス（Tailscale を含む）は、ローカル／プライベートアドレスと同様に HTTP に対応します。パブリック HTTP アドレスには引き続き HTTPS が必要です。VPN 接続を維持し、URL の変更時は既存の添付設定と認証情報を引き継いでください。Clash も使用する場合は、ほかの項目を保持したまま、TUN の経路除外とシステムプロキシの除外の両方に VPN のアドレス範囲を追加します。外出先での利用前に、スマートフォンのテザリングで未キャッシュの添付を読み取って確認してください。

原本はサーバーに保存し、ローカルには必要に応じてキャッシュします。詳細には原本の場所とキャッシュ状態（なし・一部・全体）を表示します。タグ・分類・説明は閲覧と AI/MCP 検索に利用できます。ダウンロードキャッシュの既定上限は 2 GiB で、設定で変更・削除できます。全体がキャッシュされていれば再利用できますが、未取得・一部取得のファイルには接続が必要です。アップロード待機領域は別管理で既定 10 GiB となり、キャッシュ削除では消えません。接続や認証に失敗しても、待機中のタスクと未送信ファイルを保持します。「受信済み、同期待ち」はサーバーへの保存完了ではなく、保存と検証後にのみ完了となります。認証画面やエラー HTML を添付キャッシュとして保存しません。AI/MCP は既存の個別のワークスペース読み書き権限で同じ設定・メタデータ・タスクを使用し、サーバーのパスワードは受け取りません。

既存の添付を移すには、サーバーを選び **ローカル添付の移行をプレビュー** します。既定では現在のローカル添付ディレクトリのみを分析し、プロジェクト依存を除外します。件数・容量・対象・除外を確認して **確認して移行を実行** してください。アップロード後、ストリーム読み戻しによる SHA-256 検証、旧パス対応表の永続保存、元ファイルのバージョン再確認が成功してからローカル原本を解放します。永続的なローカル原本アーカイブは追加しません。既存ノートの参照は LeafLoom 内で解決しますが、他の Markdown エディターとの互換性は保証しません。中断時は待機ファイルと進捗を保持します。サーバー設定だけで原本が移動することはなく、明示的な移行が必要です。

サーバー移行は、下記の復元可能なローカル整理とは別の処理です。既存の履歴・回収記録・過去の整理アーカイブは自動削除せず、ローカル容量を使用する場合があります。サーバー原本は別途バックアップしてください。キャッシュはバックアップにはなりません。サーバーの添付には **ファイルマネージャーで表示** はありません。

### アセット製品と Unity パッケージ

添付画面の上部で **添付ファイル** から **アセット製品** に切り替えます。先に **設定 → ファイルとインポート → 添付ストレージ → アセット製品カタログとダウンロードの一時保存** で保存先サーバーとメタデータディレクトリ（既定値 `Incoming/LeafLoomCatalog/v1`）を選び、**既存パッケージを識別** を押します。既存の `.unitypackage` 項目を登録するだけで、原本のダウンロードや展開は行いません。画面を開くだけでは公式サイトの情報を取得しません。カタログはこの保管庫で共有する一つのカタログです。サーバーの選択はその保存先を決めるもので、パッケージの絞り込みではありません。初期化済みカタログの保存先は暗黙に変更しません。

一つの製品に複数のバージョン・複製を関連付けられます。未照合のファイルも候補として表示します。ファイル名の手掛かりだけでは照合済みにせず、不明なバージョンは「不明」またはファイル名からの推定と表示します。Asset Store の公式製品 URL を貼り付け、製品名とパブリッシャーを確認して、関連付けを確認または却下します。製品の関連付けは購入権限の証明ではありません。**公式情報を取得** は明示的に開始し、取得・要確認・失敗を分けて表示します。取得できない説明・カバーは空欄のままで、代わりの画像は生成しません。リンクの記録だけでは取得完了とせず、中国語要約の未作成も明示します。

公式情報と **自分の整理** は別に保存します。公式情報を更新しても個人の製品タグ・分類・メモは保持し、既存ファイルのメタデータも別に保持します。製品情報とカバーは選択した NAS ディレクトリに保存し、ローカルに検索用の複製を保持します。同期待ち・競合を表示し、古いバージョンで新しい編集を上書きしません。

特定のパッケージで **ダウンロードを準備** を選ぶと、バックエンドが専用のローカル一時保存へストリームで取得・検証します。「検証済み・ダウンロード可能」になったものだけ取得できます。既定上限は **20 GiB** で、プレビューキャッシュやアップロードキューとは別です。画面を切り替えてもタスクを確認でき、一時停止したタスクは再試行できます。**一時保存を解放** はローカルの準備済みコピーだけを削除し、NAS の原本は削除しません。ダウンロードの有効期限は 24 時間で、期限切れ後は再準備できます。準備・取得は Unity プロジェクトを変更しません。実際のインポートは対象プロジェクトで別途確認してください。

AI/MCP も同じカタログ・タスクを使います。`vault_files` の `products`・`product`・`prepare_download`・`download_status` が検索・読み取り準備を担当し、編集・解放・再試行は接続の書き込み権限で `vault_files_update` の `product_update` を使います。編集前に現在のリビジョンを読み、同じ内容の再試行では操作 ID を再利用してください。完全なパッケージは制御されたローカル画面で直接ダウンロードし、MCP の Base64 分割転送は使いません。既存の `read` で指定するダウンロードタスク ID は従来の ZIP エクスポート専用です。Unity への自動インポートやアカウントの購入権限の検証は行いません。

## 操作手順

Base64 一括送信には、この変更を含むビルドが必要です。

ナレッジベースの添付は `vault_files_update` の `request.action="upload"` を使います。ChatGPT では `source="files"` とホストが提供するトップレベルの `files` 配列を優先します。ローカルクライアントは `source="base64"`、`name`、`data_base64`、元バイト列の `sha256` により 2 MiB 以下を一括送信できます。それ以上は begin/chunk/commit を使います。`folder` を省略すると設定済み添付フォルダーを使い、`Comics/Project/assets` などの保管庫内相対パスも指定できます。

`vault_index_status` の `workspace_revision` と一意の `operation_id` が必要です。同一引数の再試行では同じ ID を使います。結果は保存先、サイズ、SHA-256、リビジョン、`markdown_link` を返し、画像には `markdown_embed` も返します。`vault_files` の stat に `source_note` を指定するとノート相対リンクを取得できます。ノートの現在のリビジョンを使って Markdown を更新してください。同名の元ファイルは保持されます。

Design Studio のインポートや Feishu の一時転送しか表示されない場合、サーバーの `tools/list` に `vault_files` と `vault_files_update` があるか確認します。更新済みバックエンドの再起動に加え、クライアントのプラグインツール一覧を更新／再スキャンしてください。LeafLoom の再起動だけではクライアントのキャッシュは更新されません。保管庫の書き込み権限も確認してください。通常の添付に Feishu 権限は不要です。[MCP ファイルツール](mcp.md)を参照してください。

AI クライアントも `vault_files`（読み取り・ダウンロード・状態）と `vault_files_update`（アップロード・管理）で同じ添付システムを使用できます。**AI 連携** で保管庫のアクセスを有効にし、書き込みを別途許可します。チャットファイルはバックグラウンドで転送し、ローカルクライアントはサイズとハッシュを検証した分割バイト列を送れます。失敗時は完了済み結果を確認して残りを再試行してください。読み取りには現在の版が必要で、移動と回収は計画・復元記録を保持します。[MCP の設定](mcp.md)も参照してください。

サイドバーの **添付ファイル** から専用ワークスペース（`?view=attachments`）を開きます。「添付の保存先」で、すべて・ローカル・サーバー・個別サーバーを選択できます。ページ、件数、容量、種類別の件数は選択した保存先に合わせて計算します。すべての保存先ではローカルとサーバーの原本サイズを別々に表示し、個別の保存先ではその範囲のみを表示します。ローカルキャッシュは含みません。上部に総件数、使用容量、索引の状態を表示します。保管庫全体のファイル名・相対パスを検索し、種類で絞り込み、名前・更新日時・サイズで並べ替え、サムネイルと一覧を切り替えられます。初期表示はサムネイル、更新日時の降順です。1 ページ最大 100 件で、全選択は現在のページだけに適用され、ページ・検索・絞り込み・並び順の変更で解除されます。

ローカル専用モードは初回に状態のみ確認します。**ローカル目録を準備** は名前のメタデータのみ準備・更新し、整理案の作成、移動、リンク更新は行いません。ファイル位置を変更する場合は **添付を整理** で別途確認します。対応する旧索引はバックアップし、未知の版は保持します。**タスク** から保存済みの処理に再接続できます。

ファイルを選ぶと右側でプレビューできます。画像は拡大縮小、ドラッグ、画面に合わせる、拡大表示に対応し、PDF は埋め込み表示、音声・動画は内蔵プレーヤーで再生します。ファイルの切り替えや画面を離れた時に再生を停止します。狭い画面ではプレビューから一覧に戻っても条件とスクロール位置を保持します。その他の形式は詳細と元ファイルのダウンロードを表示し、デスクトップのローカル添付では **ファイルマネージャーで表示** も使えます。HTML は実行せず、SVG は画像として表示します。サムネイルはデコード容量と同時処理数を制限して必要時に生成・キャッシュし、失敗時は形式アイコンに戻ります。

**アップロード** または複数ファイルのドロップで、設定したローカル保存先（既定 `_attachments`）またはサーバーのアップロード先に追加します。同名でも両方を保持し、上書きしません。進捗と再試行はタスクで確認します。ノート（`.md`、`.txt`、`.base`）はエディターやファイルブラウザーで管理してください。選択したファイルを ZIP ダウンロード、一括移動、回収できます。名前の変更は一つずつ行います。ZIP はバックグラウンドで準備し、1 時間で期限切れになります。

名前の変更と移動は、対応する静的 Markdown のインライン・参照リンクと Wiki リンク・埋め込みを分析して計画を作成します。検出された参照、パス、ブロック項目を確認し、一度の確認で実行します。参照のある添付の回収でも対象ノートを表示し、確認を求めます。ノートのリンクは削除・書き換えず、必要に応じて添付を復元します。「検出された参照」は全参照の検出を保証する表現ではありません。本版では Office 変換、本文・OCR 検索、重複整理、一括命名テンプレートは提供しません。

### AI 素材検索と受け渡し

検索前に対象の添付グループを編集し、**AI 素材検索の対象にする** を有効にします。既定はすべて無効で、選択したグループの和集合のみを検索します。未選択時は `scope_not_configured` を返し、全添付には切り替えません。選択はグループ情報とともに NAS に同期され、競合するグループは解決するまで対象外です。通常の添付閲覧やノート参照には影響しません。

**ダウンロード → ダウンロード設定** で素材の保存先を設定し、必要に応じて準備済みローカルモデルによる意味検索を有効にします。AI は `vault_files` の `search_assets`、`asset_details`、`asset_preview` で既存のローカル／NAS 素材と実際のバージョンを確認し、`vault_files_update` の `deliver_asset` と `delivery_status` で保存します。完了時のみサービス端末の絶対パスを返します。保存済みファイルはキャッシュ削除の対象外で、プロジェクトへの組み込みは AI が行います。モデルがなくてもキーワード検索でき、パッケージ内部や画像の外観類似度は検索しません。

## 完了後の状態

同名ファイルは両方を残します。プレビュー非対応でも原本を取得できます。

## うまくいかないとき

索引が未準備なら初期化します。HTML プロジェクトの素材は保護対象です。
