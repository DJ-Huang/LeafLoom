# 一つの DUFS コンテナーで添付アカウントを分離

[English](../en/DUFS_MULTIUSER.md) · [中文](../zh-CN/DUFS_MULTIUSER.md) · [日本語](DUFS_MULTIUSER.md)

各アカウントに独立したディレクトリ、原本、資料を割り当てます。例えば DJ は `https://files.example.com/DJ/`、Alice は `https://files.example.com/Alice/` を使います。各自の LeafLoom と認証情報で接続し、管理者がサーバー設定でアカウントを管理します。自己登録は提供しません。

## ビルドと検証

標準の DUFS 0.47.0 はサーバールート外のリンクを拒否しますが、ルート内の別アカウントへのリンクを許可します。独立ユーザーを追加する前に、修正版イメージと `allow-symlink: false` を使用してください。修正はシンボリックリンクとリンクを含む親パスを拒否し、一覧、検索、ZIP と COPY/MOVE の宛先にも適用します。同じアカウント内のリンクも無効です。NAS のローカル管理者とファイル書き込みプロセスは信頼する前提で、悪意あるローカルプロセスが並行してパスを差し替える競合攻撃のサンドボックスではありません。

ARM64 Docker ホストのリポジトリルートで実行します。

```sh
docker build --platform linux/arm64 -t leafloom/dufs:0.47.0-symlink1 templates/dufs
python3 scripts/check_dufs_isolation.py --docker-image leafloom/dufs:0.47.0-symlink1
docker image save --platform linux/arm64 -o dufs-symlink1-arm64.tar leafloom/dufs:0.47.0-symlink1
```

x86-64 NAS では `linux/amd64` を指定します。Dockerfile はソースのチェックサム、ビルダーイメージと Cargo ロックを固定します。修正版は `0.47.0-leafloom.1` と表示されます。検証は一時アカウント、ファイル、ランダムなループバックポートだけを使い、ユーザーの NAS に接続しません。テスト用ハッシュには OpenSSL が必要です。終了コードが非ゼロなら配備しません。

## DJ の内容とパスワードを保持

[設定テンプレート](../../templates/dufs/config.yaml.example)を公開ディレクトリの外に保存し、プレースホルダーを既存の**完全な SHA-512 crypt ハッシュ**に置き換えます。パスワードと全体の操作設定を保持します。この構成では原本は読み取り専用、`Incoming` 内の添付と資料だけを書き込み可能にします。

```yaml
auth:
  - 'DJ:$6$REPLACE_WITH_EXISTING_SHA512_CRYPT_HASH@/DJ:ro,/DJ/Incoming:rw'
allow-symlink: false
```

[Compose テンプレート](../../templates/dufs/compose.yaml.example)で既存添付ディレクトリを `/data/DJ:ro`、既存の `Incoming` を `/data/DJ/Incoming:rw`、非公開設定を `/config:ro` にバインドします。原本のコピーや移動は不要です。`/` の権限や匿名ルールを追加せず、パスワード、ハッシュ、個人パスと復元用バックアップを Git に保存しないでください。

## Zspace Docker で切り替え

1. 元コンテナー、DUFS 設定と LeafLoom の添付ワークスペースをバックアップします。Zspace の YAML 出力は読み取り専用フラグを省く場合があるため、マウントのアクセスモードも別に記録します。旧イメージと設定を保持します。
2. 検証済みイメージ、新設定と Compose を NAS の設定ディレクトリへアップロードし、**Docker → Images → Import → Import from Zspace** からイメージを取り込みます。
3. 下書きを保存して LeafLoom を終了し、送信や資料書き込みが動いていないことを確認します。送信待ち原本と記録を保持します。旧添付コンテナーを停止し、自動起動も無効にして再起動時のポート競合を防ぎます。
4. 修正版イメージを使う Compose プロジェクトを取り込み、ポート、ネットワーク、リソース制限とマウント権限を保持します。稼働する添付コンテナーは一つだけです。停止した旧コンテナーは復元用に残せます。
5. LeafLoom の**既存接続**でアドレス末尾に `/DJ/` を付け、ユーザー名を `DJ` にします。パスワード欄は空のままで保存済みの値を保持します。接続 ID、空の `remote_root`、既定保存先、アップロード先と資料ディレクトリを維持します。版確認付き設定 API でも更新できます。
6. 旧ノートの参照、グループ、表紙、代表ファイルと件数を確認します。接続の版が変わると再走査しますが、原本全体を取得する必要はありません。未実行の旧移行計画を保持し、実行前に作り直します。旧送信記録の版は書き換えません。

検証に失敗した場合、新コンテナーを停止し、元のクライアント設定とコンテナー設定を復元します。新規データと送信待ちは保持し、同じ公開ポートで両方を動かさないでください。

## ユーザー追加・再設定・無効化

**DJ のディレクトリ外**に空のディレクトリを作り、`/data/Alice` にマウントします。固有のハッシュと `Alice:$6$REPLACE_WITH_ALICE_SHA512_CRYPT_HASH@/Alice:rw` のようなルールを追加します。既存マウントを保持して同じコンテナーを再作成／再起動し、Alice は `/Alice/` と自分のパスワードで接続します。全員が同じポートを使います。サーバーの能力を意図して変更する場合を除き、全体の操作制限を保持します。

新しい SHA-512 crypt ハッシュは `openssl passwd -6` の対話入力で作成し、パスワードをコマンド引数に含めません。再設定時は該当ハッシュだけを変更します。無効化は認証ルールを除いて再起動し、ファイルを残します。`allow-symlink: false` を維持し、ルートには実ディレクトリかバインドマウントを使ってください。
