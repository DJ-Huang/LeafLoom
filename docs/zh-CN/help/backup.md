# 备份资料、评论与恢复材料

## 使用目标

保护原始文件及不能由索引重建的用户数据。

## 开始前

先保存所有正文和 AI 草稿，暂停外部编辑及同步，再正常退出应用。

## 操作步骤

1. 备份整个关联知识库，包括隐藏的 `.vault-rag/`，并保留附件、HTML 项目及设计项目。
2. `.vault-rag/annotations.sqlite` 保存评论与高亮；历史、回收区和附件迁移原件也是恢复材料，不能当作普通缓存删除。
3. 私有设置、模型、凭据及 AI 历史位于 Windows `%LOCALAPPDATA%\VaultRag` 或 Mac `~/Library/Application Support/VaultRag`；自定义目录以实际配置为准。
4. 单独导出浏览器/桌面中的唯一未保存草稿，确保备份可读后再迁移。
5. 恢复时先使用新的本机目录检查，再决定是否替换现有资料。

如果使用附件服务器，还要备份知识库用过的每个服务器根目录中的原件（包括当前上传目录之外的原件），以及各服务器配置的元数据目录。保留存储 ID、相对路径和元数据目录的对应关系，以便恢复后打开原有笔记链接。迁移后的原件可能只在服务器上，缩略图、本地缓存和目录索引都不能代替原件。

先在独立的知识库副本中验证恢复。若有服务器附件，请连接单独恢复的测试服务器副本，确保客户端缓存为空。通过原笔记链接各打开一个本地原件和一个仅存于服务器的原件，对比原文件的 SHA-256 校验值；若使用了附件分组或封面，也检查是否恢复。能看到缩略图，不代表能打开原件。

## 完成后的表现

完整的备份应包含原始文件和用户记录。索引和回收区本身不是异机备份。

## 没有成功时

跨电脑迁移不保证系统加密凭据可用，可能需重新授权。不要把含凭据的备份公开上传。
