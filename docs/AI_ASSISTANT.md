# 使用本地 CLI 辅助知识库

网页右上角的 **AI 对话** 打开右侧面板。首次发送前选择 Codely 或 Codex；每个主题保留自己的对话，打开其他笔记不会新建会话。点击 **历史会话** 返回以前的讨论，也可新建或重命名主题。

## 准备 CLI

在运行知识库的电脑上安装对应 CLI，并在普通终端完成一次登录和模型配置。知识库沿用 CLI 的现有登录、模型及网络配置，不需要把 API Key 输入网页。后台服务所在用户需要能找到 CLI 和 Node，并访问 CLI 自己的配置与会话目录。

Windows 的 npm 安装会自动解析到对应程序或 Node 入口；macOS 使用本机可执行入口。两个平台的历史各自保存在应用私有目录，不随知识笔记同步。

Codely 当前已对照安装包 `1.0.0-rc.60` 与源码 `1.0.0-nightly.67` 的恢复扩展适配；其他版本如声明标准 ACP 会话加载能力，则使用标准接口。没有已确认恢复能力的版本会提示错误，不会用空对话替代原会话。Codex 使用其 App Server 的原生 thread 恢复。

## 引用笔记

在 Markdown/TXT 的阅读或编辑模式下选中文字，右键选择 **添加到 AI 对话**。选文加入当前发送框的引用卡片，已有问题保持原样，需要点击 **发送** 才会提交。可移除卡片，点击来源打开原笔记。

默认同时附带当前笔记；有未保存的 AI 草稿时，使用草稿正文。取消 **当前笔记** 可只发送问题和明确选择的引用。AI 可以通过知识工具检索已配置的范围，回答中的笔记链接可以点击打开。长上下文会明确提示截取，并允许 AI 分段读取完整笔记。

发送快捷键为 Ctrl / ⌘ + Enter。**停止** 保留已收到的回答和原会话。刷新网页会重新连接，不会自动重复发送；网络异常导致发送结果不确定时，使用 **重试这次发送** 查询或续用原请求。

## 应用 AI 修改

AI 提交的修改先显示为建议，展开 **查看差异预览** 核对正文。

- **接受到草稿**：只更新编辑器，显示“AI 草稿尚未写入文件”。后续手动编辑也暂停自动保存；点击 **保存草稿** 或 Ctrl / ⌘ + S 才写入文件。
- **丢弃草稿**：确认后恢复磁盘版本。刷新页面仍保留未保存的 AI 草稿和手动保存状态。
- **确认创建**：核对新笔记目录与文件名后创建，同名文件不会被覆盖。

生成建议后原文、草稿或磁盘内容有变化时，应用会停止，建议继续保留。可以重新生成，或核对后手动合并。保存沿用现有版本检查、历史记录和换行/BOM 保留机制。

AI CLI 只获得本助手的知识读取和修改建议工具，直接文件修改、任意命令执行和无关 MCP 工具受到限制。正式笔记的写入由知识库处理。

## 恢复与排查

关闭右侧面板不会删除对话；服务重启后，下次发送恢复同一个 CLI 原生会话。原生记录缺失、损坏、被其他进程占用或版本不支持时，页面会保留历史并提示恢复失败，不会悄悄换一个会话。

未检测到 CLI 时，先在终端确认 CLI 可运行，再重启后台服务，让它获得更新后的 PATH。登录过期时在终端重新登录，再发送下一条消息。升级知识库代码后需要更新安装并重启后台服务，刷新网页只重新加载当前服务。

会话、引用、建议和工作目录位于应用私有目录的 `ai/` 下；执行历史仍由 CLI 自己保存。请保留 CLI 的原生会话记录，以便长期恢复。

## 验证

自动状态与协议检查：`python -m unittest discover -s tests -p test_ai.py`。

草稿保护检查：`node tests/test_ai_drafts.cjs`，需要已安装网页构建依赖。

真实 CLI 验收：`python scripts/ai_cli_smoke.py --provider both`。它使用临时知识目录，验证工具读取、连续多轮和服务重启后同一原生会话的上下文；沿用本机登录，并会创建 CLI 自己的验收会话记录。结果保存在 `.cache/ai-cli-smoke/result.json`。
