# 飞书适配

仅在用户点名飞书、链接属于飞书/Lark，或已确认的项目来源配置指定飞书时加载。不连接飞书也可使用全部本地工作管理能力。

## 工具与权限

这些操作调用本机 LeafLoom 的飞书服务，沿用其配置的 CLI 身份和独立的飞书权限。

用本 Skill 脚本的 `feishu-inspect` 查看实际帮助及匹配的内置 Skill，再用 `feishu-read`；参数随当前版本发现，不复制过时命令。默认沿用用户身份，不换机器人身份绕过权限；不要求客户端另装全部 lark-* Skill，可通过 inspect 读取它们。工具缺失或无权限时说明能力缺口，可整理用户提供的文字/导出材料，不自动安装或改配置。

通用归档、批次与事项去重遵循 [来源采集与入库](imports.md)。新记录写 source_provider=feishu 和通用 source_kind。文档正文及同响应引用/评论 sidecar 一并归档；临时资源经 `feishu-files` 读取并转存，句柄不能作为永久附件。

## 飞书文档

适用：“把这篇文档记进某项目”“导入这个 Wiki/章节”。先读内置 `lark-doc` 及其读取参考；标题线索用 `lark-drive` 搜索，只有候选不唯一时消歧。

- URL/token 已给定时直读，支持 Docx、Wiki、章节/选区；整篇归档读取全文，局部链接按请求范围读取并标注为局部，不声称全篇。
- 保存真实 document_id、revision_id、正文及引用/评论 sidecar。评论、表格或内嵌资源有截断提示时标记 partial；独立表格/Base、转写等按内置 Skill 分流，无法展开的保留引用与原因。
- 提取需求、决策、问题、进展和候选待办。作者/归属项目与“用户已完成这项工作”不是同一件事；原文未给出的日期和贡献者不补造。

## 飞书聊天

适用：“整理今天某群/与某人的单聊”“补采本周指定工作群”。读取内置 `lark-im` 的查询参考。

- 已知会话用聊天消息列表，跨已选会话查找用消息搜索；不把关键词搜索的命中当作全天完整记录。群名/联系人有同名时解析真实标识后再读。
- 按请求的 chat_id、时间范围和身份读取，保留 sender、message_id、create/update_time 和消息链接。按返回游标分页；触达工具页数上限后仍有更多内容时保存游标、继续合法分页或标明尚未覆盖，不能声称已读完。
- 需要上下文时补读对应话题/引用，分别标注窗口外补充上下文。按讨论事项整理，不把每句聊天都造一个任务；保留关键结论的发言人、时间和源消息。
- 团队成员的工作、消息里的任务指派和你本人已完成的工作分别记录。遇到图片/语音且未读取内容，保留资源引用并说明内容未展开。

## 会议与会议产物

适用：“整理今天我参加的会议”“把这场会议/妙记的决定记下来”。读取内置 `lark-meeting` 及匹配的场景手册。

- 指定 meeting_id、妙记或纪要链接时直达相应链路。只有主题/日期时按当前用户、项目范围定位真实会议；9 位会议号先解析为真实 meeting_id，不混用标识。
- 今天的实际会议记录与日历上尚未发生的安排分别处理。日程本身不能证明出席、讨论内容或已形成决定。
- 读取可访问的 Note/用户纪要/Minutes；用户指定产物时沿指定链路。Note、Minutes 同时存在且未指定时按当前内置指南选择主链路，不自动拼接两份 AI 产物当作原始事实。
- 重新总结、决策分析或复盘时，在可访问条件下读取原始逐字稿；只有现成 AI 摘要时保留其来源限定。提取议题、决定、问题、负责人、时间及候选行动项；缺失负责人/截止时间留空。
- 无产物、未生成、无权限、部分获取分别记录。保存已经取得的资源标识供之后补采；不要根据会议标题编造纪要。

## 飞书任务映射

仅飞书任务操作读取当前内置 `lark-task` 指南与 CLI 帮助。按用户相关角色（负责、创建或关注）、已选工作项目/清单过滤并分页；项目映射缺失时不批量保存私人或无关任务。差异检查和写回遵循 [通用任务流程](tasks-reports.md)。

- 写 `source_provider: feishu`、`source_kind: task`、`source_id: <实际 GUID>`。界面 t123 编号不是 GUID；保留返回的真实链接和更新时间。
- 飞书 todo 映射本地 open、done 映射 done；本地 in-progress 是个人进展。远端任务完成时间与本人会签完成时间按语义区分，特殊完成模式、重复规则、提醒、自定义字段仍在飞书管理。
- `external_due` 保存原始 `{timestamp, is_all_day}` JSON 或 JSON null；timestamp 为数字字符串，is_all_day 为布尔值，非 null 对象必须同时具备两项。先校验再送入版本 2 比较；日期视图按已确认用户时区计算，不采用执行主机时区。不能从仅有日期的旧 due 猜测丢失的时刻。
- 远端 description 存 `external_description`，更新时间存 `external_updated_at`；正文仅作个人笔记。负责人使用稳定人员 ID，姓名不唯一先消歧。
- 用户明确要求写回时使用 `feishu-write` 和当前 CLI 中真实的创建、属性修改、负责人、完成/重开操作。成功必须由飞书确认；只推送已授权的变化字段。

## 旧飞书任务兼容

只在飞书适配中识别以下旧字段；通用流程不依赖它们：

| 旧字段 | 通用字段 |
| --- | --- |
| feishu_guid | source_id（同时补 source_provider=feishu、source_kind=task） |
| feishu_updated_at | external_updated_at |
| feishu_description | external_description |
| feishu_due | external_due（保持原始 JSON 对象或 null 的语义） |

旧 `source_kind` 的 feishu_doc、feishu_chat、feishu_meeting、feishu_task 分别映射 document、chat、meeting、task，提供缺失的 provider 依据。只在当前请求已经确定为飞书、且旧字段/旧来源配置能证明身份时补齐；来源链接和已确认项目映射也可用于核对，不把所有缺少 provider 的记录当飞书。

逐字段按“是否存在”读取：通用字段已存在就使用，空字符串或 JSON null 不能触发旧值回退。通用字段缺失时才读取相应旧值；两者同时存在且语义冲突时保留双方、置 review_state=needs_review，任务置 sync_state=conflict，停止该字段的外部写回，不静默选择一方。新旧 source_kind 的等价映射不算冲突。

在创建任务前同时查询完整通用身份与旧 feishu_guid/record_key；找到旧记录就沿用其 record_id、record_key 和同步基线。当前需操作的记录可按版本检查补齐缺失通用字段；不删除旧字段、不批量改库、不新建重复任务。历史 feishu_due 基线无需转码即可用版本 2 比较。已存在且原先一致的旧字段作为兼容副本：当前记录获得明确修改或远端确认后，在同一次版本检查更新中同步对应新旧字段，避免旧副本陈旧而在下次产生假冲突；不为新记录额外创建旧字段，发现既有矛盾仍先处理冲突。

## 页面与媒体镜像

用户指定飞书页面及子页面，或说“同步飞书工作记录”时，读 [飞书页面与媒体同步](feishu-sync.md)。保持现有脚本参数、来源清单和检查点；镜像不自动创建事项或远端任务。
