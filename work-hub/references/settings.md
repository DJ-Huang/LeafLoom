# 办公软件配置

## 位置与读写

先按入口定位当前中枢。设置页使用当前知识库配置的 `write_targets.work_hub`（默认 `工作中枢`），可在“设置 → 模板与写入 → 默认写入位置 → 工作中枢目录”调整。对话中已确认的自定义中枢与此位置不同时先说明正在配置的位置，用户要求与设置页统一时核对目录；不要自动移动旧资料或在另一个中枢重复创建记录。

软件偏好唯一保存在中枢的 `配置.md` frontmatter 中；设置页和对话修改同一文件，不在 Skill 安装目录保存用户配置。此文件可通过现有笔记工具读写，无需额外 MCP 工具或本地 CLI：

```yaml
---
work_hub:
  schema_version: 1
  office_providers: [feishu, notion]
---

# 工作中枢配置
```

- 配置不存在时使用 `[auto]`，读取不创建文件。权限失败、无法读取或格式损坏不能解释为不存在；保留文件并说明问题，不自行重置。
- 修改前读取当前笔记与版本，只更新 `work_hub.office_providers`，保留其他 frontmatter、work_hub 内未知选项、注释和正文；已有 schema_version 必须为整数 1，否则停止修改。缺失的 schema_version 可按 1 解释，保存时补齐。
- 首次保存逐级创建缺失父目录，只创建配置笔记，不初始化整个数据库。配置文件同名且无有效 work_hub frontmatter 时先说明冲突，不覆盖用户文件。
- 使用当前 workspace_revision 与笔记版本；版本冲突后重读并保留并发修改，不盲目覆盖。写入后读回配置才报告成功；保存配置不等于登录、连接或取得外部写入授权。
- 不存凭据、令牌、具体群/空间/任务清单或工作事项。这些范围沿用已确认的项目来源映射，凭据留给对应连接管理。

## 软件多选与能力

`office_providers` 是非空平台列表，允许同时使用多个真实平台，去重并保留选择顺序。平台标识为小写字母开头、最多 64 位的小写字母/数字/连字符。未知标识保留为未接入偏好，不臆造工具或执行能力。

| 平台标识 | 含义 |
| --- | --- |
| feishu | 飞书；采集、镜像与任务同步仍需相应连接和权限 |
| dingtalk | 钉钉偏好；尚未实现适配 |
| wecom | 企业微信偏好；尚未实现适配 |
| notion | Notion 偏好；尚未实现适配 |

`[auto]` 为自动按来源选择，`[local]` 为仅本地模式。两者必须分别单独使用，不能与其他平台混选。设置页勾选软件会退出这两种模式；选择模式会清除软件多选；取消最后一个软件时恢复 `[auto]`。

### 旧单选配置

schema_version 仍为 1。仅在 office_providers 字段缺失时将旧 office_provider 字符串按单元素列表读取，不因读取改写文件；列表已存在则以列表为准，空列表或错误类型不能回退旧值。保存时写列表、移除旧单选键并保留其注释、其他字段和正文。对话请求“再加上 Notion”合并已有列表，“只用飞书”才替换整个列表。

设置 API 仍接受旧 office_provider 单选请求，但已配置多个平台时拒绝旧客户端单选写入，避免无意清除其他选择，提示重新载入新版设置。新请求使用 office_providers，不同时传入两种字段。

## 实际使用规则

1. 当前请求明确的平台或链接优先，不因临时使用另一个来源改写配置。明确目标与项目映射不一致且有歧义时核对目标。
2. 未明确要求外部来源且配置为 `[local]` 时只使用本地资料，不自动采集项目来源。其他模式先采用已确认项目来源映射，没有可用映射时再参考所选平台；`[auto]` 仍有歧义则问必要目标。
3. 多选提供可用来源偏好，不授权遍历所有软件、群或空间。对明确请求与已确认范围分别采用对应适配；缺少范围时问必要目标，不按列表顺序猜测来源，也不将外部任务同时创建到多个平台。
4. 一个所选平台尚未接入、无权限或失败时，说明它的实际缺口；其他已明确范围且可读取的来源可继续处理，回执注明部分覆盖。不把 Notion 的资料转向飞书读取，可按用户提供的文字/导出材料整理。
5. 偏好不是访问控制；明确指定另一个来源仍可使用其已实现的适配，包括 `[local]` 模式下的明确请求。GitLab 代码采集依据仓库请求独立选择。
6. 仅记录工作、本地任务和生成已有资料汇报时，无论选择什么软件，都不探测办公连接。设置页即时保存；对话修改后，已打开的设置页点“重新载入设置”查看最新选择。
