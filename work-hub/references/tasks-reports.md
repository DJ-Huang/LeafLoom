# 任务与汇报

## 本地任务

直接使用 `record_type: task`、`tags: [task]`、title、status、priority、due、projects；不要求远端身份、同步状态或办公平台连接。未完成为 `open`，个人进行中为 `in-progress`，完成为 `done`。普通记录中的计划或材料行动项先作为候选；用户要求创建本地任务时持久保存。不将“完成任务”推断为一条已完成工作成果或实际工时。

## 外部任务拉取

“同步某平台任务”默认拉取并检查差异；明确要求创建、写回、完成或重开远端任务才执行外部修改。按 [入口的来源适配](../SKILL.md#按需选择来源适配) 确定目标与能力；没有已确认平台时不默认使用飞书。

以 `source_provider + source_id` 匹配任务；标识有实例/租户作用域时保留该作用域。来源链接和 `external_updated_at` 使用平台确认值。`external_description` 仅保存对外描述，个人笔记留在正文，拉取和推送都不覆盖。`due` 仅供日期视图，`external_due` 为平台原始截止对象 JSON；缺失表示未知，JSON `null` 表示明确无截止。适配负责校验、处理时区和全天语义，不得将带时刻的截止时间静默变为全天。特殊状态及不支持的字段留在原平台，不能伪造等价映射或回写未修改字段。

旧记录的兼容与增量补齐见 [工作区结构](workspace.md#已有中枢的增量兼容)，飞书旧字段映射只在 [飞书适配](feishu.md#旧飞书任务兼容) 中定义。

## 差异检查和写回

每个已关联任务存 `sync_baseline` JSON：上次已确认的 summary、description、assignees（稳定人员 ID）、due（平台原始对象或 null）、status（todo/done）。本地、远端和基线必须是同一平台、同一任务、同一表示方式。未完成状态投影为 todo，但拉取未完成状态不抹掉本地 in-progress。首次导入只从已读取的远端字段建立基线，不能用空基线清空已有内容；未知字段保持缺失。

可用 Python 时运行 `scripts/task_sync.py`，stdin 输入 `{schema_version: 2, baseline, local, remote}`，stdout 返回 pull、push、conflicts、incomplete、agreed。版本 2 对 due 的非 null JSON 对象按结构比较，不解释平台字段，需先由适配校验；不得将本地日期视图直接冒充原始对象。省略 schema_version 或指定 1 保持旧飞书截止结构校验与输出兼容，不转换已有基线。脚本只计算差异，不读写文件、不连接平台。缺少执行能力时遵循相同三方比较规则。

- 只有远端改变：刷新干净字段。只有本地改变：保留为待推送。双方同字段改变且值不同：保存双方值并置 conflict，询问如何处理；相同新值可更新基线。字段缺失列为 incomplete，不建议清空或覆盖。
- 仅拉取不能覆盖本地待推送值。外部修改前重新读取远端并比较基线；API 无条件更新能力时不能保证检查后无并发修改，仅提交明确变化字段，采用平台返回的确认值。
- 执行前持久记录 `pending_operation`（完整目标身份、字段、前值、幂等键），置 sync_state=pending。创建使用稳定幂等键；结果不确定先查询/核对该意图，禁止用新键盲目重复创建。只在远端确认的操作上更新基线，部分失败保留未完成部分。
- 使用适配提供的真实写入能力，不以本地保存冒充远端成功。姓名歧义或缺少目标时只问必要信息；用户已明确授权的操作不重复询问。
- 远端删除、权限丢失或不再可见时标记 unavailable；保留本地历史、原链接和个人笔记，不自动删除或重建。写入失败不置 synced。

## 日报、周报、复盘、年度总结

1. 明确周期/项目，默认周报为用户时区周一零点至下周一零点之前；ISO 周编号使用 ISO 年。当前周提前生成写明实际截止时刻，不能把未来日期当作已覆盖。
2. 先查询中枢日期/项目范围，分页读事实与必要来源，再按明确请求补采缺口；只生成报告的指令不隐含扫描所有外部来源。历史周报和项目资料按需引用，不迁移原件。
   生成周报或双周报时，优先读取当前中枢的 `模板/周报模板.md`，按其章节组织内容并按实际周期调整措辞；模板缺失时使用本节默认结构。模板是结构参考，不能将示例、占位符或无证据的内容写成事实；无记录时明确注明。
3. 周报包括项目进展、风险/需支持、成长和下一步；默认不展示工时，用户明确要求时再汇总。个人成果必须有贡献依据；团队背景单独说明。候选项目关联、待核实完成状态不冒充正式成果。
4. 项目复盘按目标与变更、时间线、结果、问题、原因依据、改进动作组织；推断明确标记。年度总结按项目和成果汇总，再回查重要原始证据。
5. 需要汇报工时时，只累计 activity 的 `actual_hours`，按 `record_id` 去重。task、import、项目档案、同一事项的多个项目链接与原文快照不重复累计。未知工时标为未记录，不补足目标工时，不估算分摊。
6. 写入 `汇报/`，周报名如 `2026-W44-周报.md`，其他报告明确日期/项目。已有同名时先读周期和用户编辑，版本化修订并保留人工内容；周期不同则使用带明确日期范围的名称。保存后附报告链接与覆盖缺口。发布到外部平台或发送给他人需要用户明确要求。
